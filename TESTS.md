## Критерии готовности проекта

docker-compose up поднимает всю систему: брокер, Postgres, monitor, worker.
 Monitor раз в 5 минут опрашивает минимум 3 RSS-ленты и публикует новые новости в очередь.
 Работает POST /refresh — форсирует опрос вне расписания и возвращает число новых новостей.
 Реализована дедупликация: повторный опрос не плодит дубли одной новости.
 Хендлер воркера реализован на FastStream и читает из очереди.
 Воркер выполняет NER моделью SpaCy и извлекает именованные сущности.
 Результат (новости + сущности) записывается в PostgreSQL в соответствии со схемой.
 Конфигурация подключений вынесена в .env/settings.
 ruff format и ruff check проходят без замечаний.
 Есть README.md с архитектурой, выбором брокера и инструкцией запуска.
 В README.md зафиксированы наблюдения по применению architect/editor и/или Plan/Act (что планировала дорогая модель, что генерировала дешёвая, где помогли checkpoints).

## Проверка результата
# 1. Поднять всю систему
docker-compose up --build

# 2. Проверить, что монитор жив
curl http://127.0.0.1:8000/health
# -> {"status":"ok"}

# 3. Форсировать опрос лент
curl -X POST http://127.0.0.1:8000/refresh
# -> {"new_items": N}

# 4. Убедиться, что воркер обработал сообщения и записал сущности в БД
docker-compose exec postgres psql -U postgres -d news -c \
  "SELECT n.source, n.title, e.label, e.text FROM news n JOIN entities e ON e.news_id = n.id ORDER BY n.created_at DESC LIMIT 20;"


Признак успеха: после /refresh в таблице news появляются свежие новости из разных агентств, а в entities — извлечённые SpaCy сущности (персоны, организации, локации), связанные с новостями.
